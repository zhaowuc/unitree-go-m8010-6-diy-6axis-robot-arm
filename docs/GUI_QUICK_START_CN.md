# V15.30A-FT 机械臂中文控制界面快速上手

本版本把七台电机映射为 J1～J6 六个逻辑关节，在同一窗口中显示现实与虚拟滑条、目标、实际角度、误差和状态。所有角度都是本次启动捕获的 `SESSION_REFERENCE_V1` 会话相对角度；不是永久机械零位。程序不修改电机内部零位，计算机辅助设计零位和机器人系统零位仍为待定。

## 启动

1. 确认机械臂周围已清空，现场有人可随时断电，各关节具有计划运动所需的机械净空。
2. 在 Ubuntu 图形桌面终端中进入仓库根目录。首次启动需联网安装已锁定的 Python 依赖。脚本会优先使用已安装 `libxcb-cursor0` 的 XWayland；如果该包缺失，则使用当前 Wayland 桌面。
3. 执行：

```bash
./start_arm_gui.sh
```

脚本会先校验冻结 MuJoCo 模型哈希、图形会话、串口占用、端口和运行环境，再构建两个最小 ROS2 包与 GO 控制器。界面默认为“现实驱动虚拟／停止制动”，启动本身不会发起任何运动。

## 停止

正常停止时，先点击红色“停止并制动”，确认状态后关闭主窗口。也可在启动终端按 `Ctrl+C`。顶层脚本会绕过 ROS2 命令路由，直接向 J1、J2、J3/J4/J5 和 J6 四个故障域反复发送制动／失能，然后回收受管进程。这个外部停止广播带有会话终止栅栏；一旦发送，本次 worker 会话不能再次使能，必须完整退出并重新启动。

## 现实驱动虚拟

点击“现实驱动虚拟”后，现实编码器是显示源。现实六个滑条、虚拟六个滑条和 MuJoCo 都跟随 `/joint_states`。该模式会请求硬件制动，只做镜像监视。

## 虚拟驱动现实

点击“虚拟驱动现实”后，可编辑虚拟滑条或精确输入。编辑值只是待执行目标，会立即显示在 MuJoCo 中，但不会直接让真机运动。只有点击“执行目标姿态”才会锁定并下发当前目标。

## 位置模式

1. 确认所有计划运动的关节均显示健康连接，且至少有一个关节健康。未连接或故障关节由所属底层故障域维持制动，不会因其他健康轴进入位置模式而解除制动。
2. 点击“虚拟驱动现实”和“位置模式”。
3. 设置会话相对目标，第一版硬限定为每轴 -10°～+10°。
4. 点击“执行目标姿态”。默认速度上限为 5°/秒，加速度上限为 20°/秒²，控制周期为 100 赫兹。
5. 实际误差在 0.5° 内连续 0.5 秒后，状态从“已到位”转为“保持中”。超时仍未到位会显示“未到位”并触发对应故障域的安全处理。

## 力矩开启与保持当前位置

在关节状态与硬件状态流新鲜、且至少一个关节健康时，“力矩开启”和“保持当前位置”会先锁定当前编码器位置，再请求健康关节主动保持；未连接或故障关节仍由所属底层故障域维持制动。保持状态下编辑虚拟目标不会改变真机指令，可避免绕过“执行目标姿态”。

## 力矩关闭与可拖动模式

“力矩关闭”对 J1/J3/J4/J5 发送全零 FOC 指令，对 J2 保持制动，对 J6 发送并核验失能；这不代表切断 24V 或主电源，24V／主电源仍可能接通。“可拖动模式”先显示中文危险提示，确认后执行同样的低／零驱动力请求，但仍持续监视编码器。本版本没有零重力补偿，J3 等重载关节可能因自重下落；必须先可靠支撑机械臂。

## 设置与返回初始化姿态

“设置初始化姿态”和“回到初始化姿态”都要求六个关节状态新鲜且全部健康连接，因为这两项操作处理完整六轴姿态。“设置初始化姿态”原子保存当前六轴相对位置与会话标识。“回到初始化姿态”只接受当前会话的有限值；重启、参考改变或文件无效时会提示“初始化姿态需要重新设置”，不会运动。

## J2 当前限制

J2A/J2B 在同一物理总线中原子监视，逻辑角为双电机映射后的平均值。双电机同步误差绝对值超过 1° 会立即对两台电机制动。J2 最终负载跟踪尚未通过，因此 V15.30A 命令路由把所有拖动、保持和位置请求对 J2 强制改写为 `BRAKE`；J2 只保留实时反馈和同步监视。界面固定显示“J2最终负载跟踪待解决”；J2 主动控制阻塞不会阻断 GUI、ROS2、MuJoCo 或 J1/J3/J4/J5/J6。

## 紧急停止

首选点击红色“停止并制动”。如界面无响应，在启动终端按 `Ctrl+C`，顶层脚本仍会直接广播带会话终止栅栏的制动／失能。也可在仓库根目录执行 `python3 tools/hardware/v15_30a_gui_stop.py`；执行后不得在原 worker 会话继续操作，必须完整退出并重新启动。如果机械臂继续运动、终态日志未确认、J2 同步异常或任何现场情况超出预期，监护人应立即人工断电。协议制动／失能不等同于经认证的安全扭矩关断。

## 运行记录

每次运行的日志保存在 `logs/arm_gui/<时间>/`，不写入最小验收证据目录。最小验收证据只位于 `hardware/v15_30a_gui/`。
