# V15.31A-FT GUI 快速上手

当前机械臂断电，本页不构成上电或实机运动授权。重力节点 → Router → GO 的软件前馈链已接通，但冻结 `gravity_control.yaml` 明确设置 `continuous_rotor_limits_authoritative=false`；再加上当前没有与真实硬件会话、状态实例和编码器分支绑定的 `MODEL_SESSION_ANCHOR_V2`，系统必然 fail-closed，`Tff=0`，现实 POSITION 不可用。只有另行完成现场安全 gate、有效 anchor、连续承载与方向验证，并通过受审计的新配置／哈希解除 authority 后，才可进入第 5 步。

1. **调整目标滑条**：只使用“计划目标”中的唯一一组 J1～J6 滑条或精确输入。编辑只改变虚拟目标并使旧 `PLAN_TOKEN` 失效，不会控制真实电机。

2. **预演轨迹**：点击“预演轨迹”。系统从当前真实编码器姿态生成同一份分段 quintic 配方，播放计划动画，并检查关节限位、碰撞、速度、加速度、重力与热负载。任一检查未通过，或 anchor／连续力矩 authority 缺失时，不得下发。

3. **查看双 MuJoCo**：左侧“计划／虚拟机械臂（不代表真机）”显示目标和计划轨迹；右侧“现实机械臂数字孪生（仅编码器）”只跟随真实反馈。两者使用独立 `MjData` 和独立后台单线程渲染器；两者不一致表示计划与现实存在差异，不能把左侧当作真机状态。

4. **确认系统状态**：查看“当前任务状态”和七行“物理电机状态”。只有当前状态显示“预演通过”（当前阶段为等待用户下发）、反馈与通信新鲜、七电机在线健康、温度允许、重力 anchor 有效、模型／配置哈希一致、连续转子力矩 authority 有效且没有限位／碰撞／热 blocker 时，才具备现实下发条件。当前冻结配置不满足这一条件。

5. **下发到现实**：仅在现场另行授权且第 4 步全部满足时，明确点击“下发到现实”。一次性 `PLAN_TOKEN` 被消费后，真机执行刚才预演的同源轨迹；调整滑条本身永远不会触发这一步。当前断电阶段不要点击。

6. **恢复初始化**：点击“恢复初始化姿态”只会先载入与当前 persistent software reference 和文件哈希严格绑定的初始化姿态并执行虚拟预演；预演通过后仍须按第 5 步明确下发。默认无效或仅绑定旧 `SESSION_REFERENCE_V1` 的 authority 会被拒绝，系统不运动并提示重新建立姿态 authority。

7. **停止并制动**：需要终止任务时点击红色“停止并制动”，并以控制器反馈确认各 GO 故障域 BRAKE、J6 DISABLED。协议制动／失能不等于认证的安全扭矩关断；重载关节必须可靠支撑，异常时由现场人员使用可触达的急停或人工断电。
