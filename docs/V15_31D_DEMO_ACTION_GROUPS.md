## 已实现的入口

在 Linux 控制机的仓库根目录，可使用已打包的现场演示入口：

```bash
python3 tools/hardware/v15_31d_demo_session.py --execute --cycles 3 --supported --vertical --hands-off --clearance
```

四个现场标志须与实际情况一致。入口建立独立新会话，执行同一动作文件的
1～3 次 J1 1°往返，并保存结果、退出后核对制动终态。不带 `--execute` 只检查。
只有确实再次断电后才添加 `--power-cycled`，让原工具恢复 J6 的本次 POS_VEL 模式；
正常重复使用已完成的模式配置，J6 驱动仍会读取并核对实际模式，不重复写入 RID10。
具体依赖和证据目录见 `tools/hardware/v15_31d_demo_templates/README.md`。

在正常机械臂 GUI 顶部打开“动作组”。添加虚拟目标或捕获有新鲜反馈的实姿，
编辑六关节目标、速度、停留和夹爪动作；保存或加载 UTF-8 JSON。
编辑和加载不发送运动。J2 始终是双电机共同驱动的一个关节，J6 仍是 DM-G6220。

动作文件使用 `go-m8010-action-group/1.0`，目标为**模型绝对角度（度）**，
并保存模型 SHA256。执行时转换到当前会话角度，不把上一会话的相对角直接重放。
运行前须已有当前会话的健康六轴 HOLD 和有效运行权限。

“执行动作组到现实”逐步复用原 GUI 的完整预演、PLAN_TOKEN、逐轴分段和实际反馈。
确认到位并保持后才处理夹爪及停留。运动中暂停调用原停止保持逻辑，
恢复时从新反馈重新预演当前步骤；停留时暂停冻结剩余等待。
“停止动作组并保持”清除剩余步骤，不额外开闭夹爪；真正的保持状态以硬件反馈为准。
通信、会话、温度、重力权限、路由异常使动作组失败，不自动恢复旧轨迹。
动作组运行期间禁止手工编辑或其他模式抢占；原制动入口仍可使用。

每轮结果写入原 GUI 日志目录的 `action_group_*.jsonl`，记录动作文件、会话绑定、
步骤事件、测得的到位角和误差。单次发送成功不等于硬件到位。

## 演示标准和严格标准

| 用途 | 到位与保持标准 | 结论范围 |
| --- | --- | --- |
| 动作组演示 | 六轴误差不超过 0.25°，静止 HOLD 连续 0.5 秒；沿用原碰撞与保持检查 | 仅用于本演示动作组，不代表真实抓取精度已验证 |
| 原严格定位验收 | 仍使用 0.1° 契约；原 GUI 的 J6 0.08°配置保留 | 完整实机验收尚未完成 |

0.25°沿用当前执行链已有的 HOLD 跟踪窗口，不增加碰撞、速度、力矩、温度或同步许可。
动作组结束后恢复原到位跟踪器、速度和保持策略。真实物体抓放仍需按开口、目标大小和实测
记录重复次数、成功次数及失败原因；尚无实测依据，不能宣称任务抓放通过。

## 夹爪状态

用户于 2026-09-06 确认：PWM 舵机，尚无控制板，计划使用 ESP32-P4。
因此动作文件可以记录 `none/open/close/set`，`set`使用开度百分比，另有等待时长；
**含实际夹爪动作的组在实机启动前明确拒绝**。没有猜测串口协议、GPIO或PWM端点。
开度百分比不等于毫米，也不代表完成物理标定。以后接入控制板时实现实际传输与标定；
无夹持反馈时只能报告命令已发送和等待结束。

## 可复现的软件闭环

在仓库根目录运行：

```text
python tools/demo_action_group.py --check-controls --output action_group_demo_result.json
```

默认加载 `examples/action_groups/pick_place_demo.json`，复用生产逐轴五次轨迹生成器，
以合成采样运行五步动作及模拟夹爪顺序，并检查运动中暂停、重新规划、恢复和停止。
程序不打开 ROS、UDP、串口或电机。结果明确标注 `SOFTWARE_SIMULATION_ONLY`，
没有碰撞证明，也没有真实抓住物体的证据。示例不是实机抓放处方。

当前硬件恢复及设角保持证据另见 `V15_31D_HARDWARE_STATUS_20260906.md`。

## 当前实机结果

已验证当前位置支撑 HOLD 约 10 秒，以及一次保存→加载→预检→实机两步往返。
单次 J1 去程约 1.143761°、回程残差约 0.144054°，包含 J2–J5 小幅修正段；
这是演示标准下的单轮 PASS，不是严格 ±0.1°或三轮重复性通过。

用户已澄清前次 J6 变化来自手动调整；后续 J6 静止复测 500 帧/50.033 秒 PASS，
GO 六机的新 BRAKE 采样及三域终态也均 PASS。达妙为原生 USB-CAN 接口，已在
`lsusb` 观察到 `34b7:6877`，串口列表缺项不能认定它掉线。
最新三轮请求仍在动作前因 J2 启动映射受阻：J2B 诊断估算约 2.211498°，
超过原 2°恢复窗口；该估算不是授权坐标，未据此修改阈值或校准。
实际执行轮数仍为 0，原因待 J2 移动/相位连续性澄清；原失败记录保留。
